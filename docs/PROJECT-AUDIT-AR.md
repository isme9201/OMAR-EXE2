# تدقيق Avenmedia — التطبيق، الرفع، PDF، وقاعدة البيانات

## النتيجة المختصرة

- **Supabase:** عُثر على المشروع النشط باسم `Omar masri`/`omar-masri`، والمعرّف الداخلي يطابق المرجع الموجود في التطبيق. فُحصت أسماء الجداول والأعمدة فقط؛ لم تُقرأ سجلات العملاء والموظفين ولم تُجرَ أي كتابة على قاعدة البيانات.
- **الرفع:** رابط Cloudflare المنشور حالياً يُرجع 404 لكل من `/upload` و`/client-upload.html`. وظيفة Supabase الحية موجودة وتردّ `410` للتوكن التجريبي غير الصالح، وهي الاستجابة الصحيحة. أصلحت صفحة الرفع المقترحة: مفتاح المشروع المرفق كان لمعرّف مختلف، والـ HTML كان يستدعي `list_uploads` غير المدعوم؛ أصبح يتحقق من الرابط عبر `sign_upload` ويعرض الواجهة المرفقة بعد نجاح التحقق. يلزم نشر ملفات `out/` كي تتوقف روابط الموقع الحية عن 404.
- **الطلبات والموظفون:** كتالوج موحّد لستة تخصصات يربط نوع الطلب بالتخصص/المنفذ المناسب. أُضيف تحقق من القيم في Edge Function لإنشاء الحساب أيضاً، وليس في النموذج فقط.
- **PDF:** جرى توحيد حفظ ملفات PDF وفتح مجلد التنزيلات في Tauri. أُضيفت خطوط Amiri وتشكيل عربي واتجاه RTL لعدم فشل ملفات PDF التي تتضمن أسماء العملاء أو تفاصيل عربية.
- **الحزم:** اكتملت عمليات ترجمة Windows x64 وmacOS ARM64 وIntel وLinux x64 والويب بنجاح في GitHub Actions؛ لكن GitHub منع رفع الملفات الوسيطة لأن حصة تخزين Actions ممتلئة. عُدّل سير العمل لتجاوز تخزين Actions artifacts: التشغيل اليدوي يرفع الملفات مباشرة إلى **مسودة إصدار** خاصة بالمستودع (ولا ينشرها للعامة)، ورفع main لا ينشر الإصدار إلا بعد اكتمال جميع المنصات. لم أعد تشغيله بعد هذا التعديل.

## نقاط قاعدة البيانات

### أمان — يلزم قرار سياسة قبل التنفيذ

أعاد Supabase تنبيهاً حرجاً: جدول `public.client_orders` لديه RLS معطّل. يحتوي الجدول حالياً على صفر صفوف وفق إحصاء المخطط، لكن وجود مفتاح anon في تطبيق العميل يجعل سياسات الوصول مهمة. **لم أفعّل RLS**، لأن التفعيل بلا سياسات يمنع الوصول، ولأن سياسة العمل المطلوبة (من يستطيع القراءة/الكتابة؟) تحتاج قراراً منك.

الأمر الذي اقترحه فحص Supabase هو:

```sql
ALTER TABLE "public"."client_orders" ENABLE ROW LEVEL SECURITY;
```

لا تشغّله وحده قبل تحديد وإضافة السياسات المناسبة. يجب أولاً توضيح هل يستخدم هذا الجدول مسار رفع عام، وما نوع الطلبات التي يجب أن تسمح بها الواجهة.

### المالية — Migration غير منعكسة في المخطط الحي

كود المالية يستعمل `avenmedia_accounts` و`avenmedia_transactions`، والـ migration المحلي `20260917_avenmedia_management_finance_rls.sql` ينشئهما. لم يظهر الجدولان في قائمة جداول المشروع الحي، لذا يبدو أن الـ migration غير مطبّق أو أن بيئة النشر لا تطابق هذا المشروع. **لم أطبّق migration**؛ فهو يتضمن إنشاء جداول وسياسات وتعديلات صلاحيات. راجعه قبل تطبيقه، وبعدها أعد اختبار صفحات المالية والتقارير على البيانات الحقيقية.

## PDF: أين وماذا تغيّر

تم جرد نقاط إنشاء PDF: كشف الحساب الشهري، دفتر المالية، سجل الطلبات المتأخرة، جداول الموظفين، وتصدير مهام الإنتاج. الخطوط القياسية السابقة لا تدعم الحروف العربية، ما كان قد يرمي استثناء عند تضمين نص عربي. أضيف دعم خط عربي مع اختبار انحدار مشترك؛ ويستخدم سطح المكتب Tauri حفظاً أصلياً داخل Downloads ثم يفتح المجلد. متصفح الويب يبقى خاضعاً لقيود المتصفح على فتح مسارات النظام، ويستخدم رابط تنزيل/ملف بدلاً من فتح مجلد Downloads قسراً.

لم يتم إجراء تسجيل دخول أو إنشاء حساب موظف أو رفع ملف حقيقي أثناء الاختبار.

## رابط المحادثة السابقة

الرابط الذي أرسلته يعرض حالياً «This page doesn't exist»، لذلك لم يمكن قراءة تفاصيله. خارطة UI/UX المنفصلة بُنيت على المستودع، دليل UI/UX المرفق، ومخطط قاعدة البيانات الحية.
